# Adding a new trip to the daily digest

The daily email is generated by scanning every trip the runner can see.
**You have two places to put a trip**, depending on whether the trip is
personal or you're okay with it being world-readable:

| Where | Visibility | When to use |
|---|---|---|
| **`TRIPS_CONFIG` GitHub Secret** (private) | Encrypted, only repo owner sees it | **Default for your real trips.** Dates, destinations, points balances stay private even if the repo is public. |
| **`config/trips.yaml` file** (committed to the repo) | World-readable if the repo is public | Generic examples, smoke trips, or stuff you don't mind sharing |

Trips defined in the secret take precedence over file trips with the same
key, and the daily run merges both before deciding what to dispatch.

## Quick recipe (private trip via the secret)

1. On GitHub, open your repo → **Settings → Secrets and variables → Actions**
2. Find **`TRIPS_CONFIG`** in the list
   - If it doesn't exist yet, click **New repository secret** and name it `TRIPS_CONFIG`
   - If it does, click the pencil icon to edit
3. The secret value is a YAML block like this:
   ```yaml
   trips:
     my_new_trip:
       name: "My descriptive name"
       enabled: true
       origin: "ORD"
       # ... rest of the trip fields, see template below
   ```
4. Paste your YAML, click **Save** (or **Update secret**)
5. Next daily run picks it up. To run it now: **Actions → Daily Flight Digest → Run workflow → all**

You can put **multiple trips** under one `trips:` key in the same secret —
just keep adding entries. Each gets its own section in the email.

## Quick recipe (public example trip via the file)

1. Open `config/trips.yaml` on GitHub
2. Click the pencil icon to edit
3. Copy the template below into the `trips:` block, change the values
4. Commit → next daily run picks it up

## Template (copy-paste this)

```yaml
  my_new_trip:                      # ← pick a unique key (lowercase, underscores)
    name: "My descriptive name"     # ← shown in the email header
    enabled: true                   # ← set to false to silence without deleting
    origin: "ORD"                   # ← your home airport IATA code
    final_destination: "GRU"        # ← main international destination
    brazil_gateways: ["GRU", "GIG"] # ← alternate intl arrival airports (optional)

    stopovers:
      candidates: ["ADZ", "CTG", "AUA"]  # ← airports where you'd overnight in transit
      min_days: 2                        # ← shortest acceptable stopover length
      max_days: 4                        # ← longest acceptable stopover length

    through_tickets:
      enabled: true                 # ← include one-PNR options (e.g. ORD→NVT direct)

    domestic_leg:
      origin: "GRU"                 # ← where the domestic leg starts
      destinations: ["NVT", "JOI", "FLN"]  # ← all valid final cities
      airlines: ["LATAM", "GOL", "AZUL"]

    travel_window:
      earliest_depart: "2026-07-26"
      latest_depart: "2026-08-02"
      return_by: "2026-08-10"

    points_balances:                # ← your balances per program
      amex_mr: 180000
      lifemiles: 45000
      c6_atomos: 0

    cpp_valuations:                 # ← cents per point you value each program at
      lifemiles: 1.4
      aeroplan: 1.8
      united_mp: 1.2
      flying_blue: 1.5
      smiles: 1.3
      latam_pass: 1.2
      tudoazul: 1.1

    scoring_weights:                # ← how the digest ranks combos (sums to 1.0)
      total_cost: 0.5
      total_time: 0.3
      connection_quality: 0.2

    constraints:
      gru_min_connection_hours: 3   # ← reject combos with shorter GRU connections
      max_total_travel_hours: 36    # ← reject combos over this total travel time
      baggage_checked_bags: 1

    notify:
      email: ""                     # ← leave blank; env var RECIPIENT_EMAIL wins
      send_time: "07:00"
      only_if_change: false
```

## Field guide (what each key means)

| Field | What it does |
|---|---|
| `name` | Human-readable label shown in the email section header |
| `enabled` | Set to `false` to stop the daily cron from including this trip without deleting it. Defaults to `true`. |
| `origin` | Your home airport (IATA 3-letter code) |
| `final_destination` | The primary international airport — used for `ORD → GRU` direct combos |
| `brazil_gateways` | Alternate entry points for the intl→domestic handoff. For Brazil: `["GRU", "GIG"]`. If you omit this, only `final_destination` is used. |
| `stopovers.candidates` | Airports where you'd break up the journey overnight (Caribbean islands for South America, etc). Empty list = no stopover combos enumerated. |
| `stopovers.min_days`/`max_days` | How long you'd stay in the stopover city |
| `through_tickets.enabled` | Also enumerate single-PNR options (one ticket for the whole trip). These are flagged `🎫 SINGLE TICKET` in the email because the airline protects connections. |
| `domestic_leg.destinations` | The actual final cities you're going to. Multiple entries = each is a separate combo. |
| `travel_window` | Search every departure date between `earliest_depart` and `latest_depart`; every return must be before `return_by`. |
| `points_balances` | Your current balances per program. Used to check affordability for award options. |
| `cpp_valuations` | How much you value 1 point of each program, in cents. Used to convert miles+taxes into an "equivalent USD" for ranking cash vs points. |
| `scoring_weights` | How the ranker weighs cost (0–1), time (0–1), and connection quality (0–1). Must sum to 1. Defaults emphasize cost. |
| `constraints.gru_min_connection_hours` | Reject combos with a shorter intl→domestic gap at GRU/GIG. |
| `constraints.max_total_travel_hours` | Reject combos whose total trip time exceeds this. |

## Simpler trips (no stopovers, no Brazil domestic)

You don't have to fill in every field. Minimal template for a simple trip
without Caribbean stopovers or domestic leg:

```yaml
  new_york_to_tokyo_dec2026:
    name: "NYC → Tokyo December 2026"
    enabled: true
    origin: "JFK"
    final_destination: "HND"
    brazil_gateways: ["HND", "NRT"]     # both Tokyo airports
    stopovers:
      candidates: []                    # no Caribbean-style stopover for this trip
      min_days: 1
      max_days: 1
    through_tickets:
      enabled: true
    domestic_leg:
      origin: "HND"
      destinations: ["HND"]             # no onward domestic leg — same as arrival
      airlines: []
    travel_window:
      earliest_depart: "2026-12-15"
      latest_depart: "2026-12-22"
      return_by: "2027-01-05"
    points_balances: { amex_mr: 180000 }
    cpp_valuations: { flying_blue: 1.5, aeroplan: 1.8 }
    scoring_weights: { total_cost: 0.5, total_time: 0.3, connection_quality: 0.2 }
    constraints: { gru_min_connection_hours: 3, max_total_travel_hours: 30, baggage_checked_bags: 1 }
    notify: { email: "", send_time: "07:00", only_if_change: false }
```

## After you commit

- Next morning's scheduled run (08:00 CT) includes your new trip automatically
- Want to test right away? **Actions** → **Daily Flight Digest** → **Run workflow** → pick **all** (default) → **Run**
- You'll get a single email with one section per enabled trip

## Silencing a trip temporarily

Set `enabled: false` on that trip. The rest keep running. Flip back to
`true` when you want it again. Nothing else in the config needs to change.

## Troubleshooting

- **"Unknown trip 'xyz'"**: you picked that key from the dispatch dropdown but
  renamed it in the YAML. Update `.github/workflows/daily_run.yml` to match,
  or just pick `all`.
- **Email has 0 ranked combos for your new trip**: your date window may not
  have fare data yet (>11 months out), or all combos got pruned by your
  `max_total_travel_hours`. Loosen constraints or pick closer dates.
- **Ran workflow but no email arrived**: check the workflow Logs tab for
  errors, and confirm `SENDGRID_API_KEY` + `SENDGRID_FROM_EMAIL` +
  `RECIPIENT_EMAIL` are set in repo secrets.
